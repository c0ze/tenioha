# てにをは / Tenioha

*[English](README.md) · 日本語*

てにをはは、日本語の助詞を関数シグネチャの検査対象とする実験的な関数型言語である。
呼び出しでは、各引数は位置ではなく助詞によって仮引数に束縛される。したがって助詞が
相異なるかぎり、引数は語順を入れ替えてよい。実装は Python による参照インタプリタで
あり、外部パッケージに依存しない。

> *てにをは* は日本語の文法助詞を指す伝統的な呼称であり、て・に・を・は そのものに
> 由来する。慣用的には文の文法的な整合性を指し、助詞の誤った文について
> 「てにをはが合わない」と言う。

## 現状

版は 0.7.1。インタプリタは、型付きの助詞呼び出し、ユーザー定義の関数と手続き、不変
束縛、再帰、遅延評価される条件、検査される I/O、代数的データ型、明示的なジェネリク
ス、入れ子コンストラクタの網羅的マッチ、関数値、モジュールを備える。ジェネリックな
リストとオプションのライブラリを同梱する。無名の関数と手続きは、不変なレキシカル値
を捕捉する。マッチは順序付きのアームとワイルドカードのフォールバックを取り、被覆
されないケースと到達不能なアームは実行前に拒否される。助詞は整数および閉じ括弧に
密着してよいが、識別子となる語は明示的な境界を保つ。明示的な別名と仮引数ごとの助詞
選択は、型・効果・正規の引数順序をいずれも保存する。

0.7.1 では、深く入れ子になったジェネリック型でのクラッシュを修正し、ファイル読み込み
と埋め込みの双方で入力の扱いを統一した。ファイル中の文字列リテラルに含まれる CR お
よび CRLF は、元の文字のまま保持される（従来のファイル復号は LF に変換していた）。
コメントと診断の位置情報は文書に記載した改行規則に従い、すべての入力経路が先頭の
BOM をちょうど一つだけ受け付ける。

## 着想

多くの言語では、引数の意味は位置から決まる。

```python
subtract(5, 3)   # どちらが被減数かは、表記されない
```

てにをはは、引数の役割を助詞で識別する。

```text
(5 から 3 を 引く)
(3 を 5 から 引く)
```

いずれも「5 から 3 を引く」であり、結果は `2` である。`から` が起点を、`を` が引く量
を指す。シグネチャが検査するのは助詞と、値の通常の型（たとえば `整数`）である。

助詞のラベルが相異なる引数は、束縛先を変えずに移動できる。ラベルの欠落・重複・誤り
はいずれもコンパイルエラーである。引数は純粋な式でなければならず、入出力は明示的な
列に属する。語順の入れ替えという規則が厳密になるのは、これらの制限があるためである。

型検査は、いずれの式を実行するよりも前にファイル全体を対象として行われる。たとえば
`(3 に 5 に 足す)` は、`に` の重複と `を` の欠落を位置情報付きで報告する。入れ子に
した `(読む)` は入力を読む前に拒否される。手続き中またはファイル先頭で
`名前 は (読む)` と束縛し、`名前` を純粋な引数として渡す。

## 実行

Python 3.11 以上。パッケージの導入もインストールも不要である。動作確認は Python
3.11.15 と 3.14.7 で行った。

```sh
git clone https://github.com/c0ze/tenioha.git
cd tenioha
python -m tenioha --eval '(5 から 3 を 引く)'
python -m tenioha examples/hello.ten
python -m tenioha examples/arithmetic.ten
python -m tenioha examples/factorial.ten
python -m tenioha examples/fibonacci.ten
python -m tenioha examples/fizzbuzz.ten
python -m tenioha examples/primes.ten
python -m tenioha examples/gcd.ten
python -m tenioha examples/collatz.ten
python -m tenioha examples/times_table.ten
python -m tenioha examples/power.ten
python -m tenioha examples/binary.ten
python -m tenioha examples/palindrome.ten
python -m tenioha examples/sort.ten
python -m tenioha examples/greeting.ten < examples/greeting.in
python -m tenioha examples/lists.ten
python -m tenioha examples/options.ten
python -m tenioha examples/closures.ten
python -m tenioha examples/closure_greeting.ten < examples/closure_greeting.in
python -m tenioha examples/nested_patterns.ten
python -m tenioha examples/compact.ten
python -m tenioha examples/aliases.ten
python -m tenioha --check examples/factorial.ten
```

最初のコマンドは `2` を、factorial は `720` を出力する。greeting の例題は入力
フィクスチャから `Ada` を読む。lists の例題は、ジェネリックなリストに対する map と
fold の後に `3` と `12` を出力する。`--check` は、呼び出されていない関数本体と
インポートしたモジュールを含めてファイル全体を検査し、プログラムの I/O は実行しない。
`--pure` は最上位の文が純粋であることを要求する。ファイル実行では明示的な `表示する`
の出力のみが印字され、`--eval` では単位型でない式の結果も印字される。

テストの実行:

```sh
python -m unittest discover -s tests -v
```

## 最初のプログラム

```text
; 整数の結果は、表示する前に明示的に変換する。
(((5 から 3 を 引く) を 文字列にする) を 表示する)。
```

ソースは UTF-8 の `.ten` ファイルとして保存する。`;` は行コメントを開始し、`。` は
省略可能な文終端である。入れ子の呼び出しには括弧が必要である。助詞は数値および閉じ
括弧に密着してよい。

```text
(((5から 3を 引く)を 文字列にする)を 表示する)。
```

これも `2` を出力する。識別子となる語は空白を保つ。`値 を` は名前と助詞であり、
`値を` は一つの名前である。完全に連結した `5から3を引く` は受理しない。

関数は、仮引数の助詞と返り値の型を宣言する。

```text
関数 差 (元: 整数) から (量: 整数) を -> 整数 {
    (元 から 量 を 引く)
}

答え は (3 を 5 から 差)。
((答え を 文字列にする) を 表示する)。
```

別名と助詞の選択は明示的に宣言する。

```text
関数 加える (元:整数)に|へ (量:整数)を -> 整数 {
    (元 に 量 を 足す)
}
別名 加えます は 加える。
(((5へ 3を 加えます)を 文字列にする)を 表示する)。
```

これは `8` を出力する。`に|へ` は一つの仮引数に対していずれかの助詞を受け付けるが、
両方を与えるのはエラーである。この選択は、関数値・クロージャ・インポートを通じて型の
一部として保たれる。`別名` は綴りを宣言するだけであり、自動的な活用も効果の変更も
伴わない。他の例は [aliases.ten](examples/aliases.ten) にある。

代数的データ型は、関数と同じ助詞の規則でコンストラクタを宣言する。

```text
型 選択<T> { 無し。有り (値: T) を }

値 は (42 を 有り<整数>)。
答え は 場合 値 {
    (無し) なら { 0 }
    (数 を 有り) なら { 数 }
}。
((答え を 文字列にする) を 表示する)。
```

マッチはコンストラクタの組み合わせをすべて被覆しなければならない。`参照 引く` は
関数値を生成し、`(5 から 3 を 適用 参照 引く)` はそれを適用して `2` を返す。関数型は
助詞の順序と効果を保存する。ジェネリック関数、マッチ、相対モジュールのインポートに
ついては[言語ガイド](docs/LANGUAGE.md)を参照。

関数名を省略するとクロージャになる。次の各結果は、それぞれの生成時の増分を保持する。

```text
関数 加算器 (増分: 整数) で -> 関数[整数 を -> 整数] {
    関数 (値: 整数) を -> 整数 { (値 に 増分 を 足す) }
}

十増やす は (10 で 加算器)。
(((5 を 適用 十増やす) を 文字列にする) を 表示する)。
```

これは `15` を出力する。クロージャの生成は本体の評価を遅延させるが、本体全体は
プログラムの I/O より前に検査される。無名の `手続き` 値は IO 効果を保持する。

パターンは複数のコンストラクタ階層を一度に分解できる。最初に一致したアームが実行され、
`_` が残りのケースを受け持つ。

```text
型 選択<T> { 無し。有り (値: T) を }
値 は ((42 を 有り<整数>) を 有り<選択<整数>>)。
答え は 場合 値 {
    ((数 を 有り) を 有り) なら { 数 }
    _ なら { 0 }
}。
((答え を 文字列にする) を 表示する)。
```

これは `42` を出力する。網羅的でないマッチは被覆されていないパターンを報告し、先行の
アームに完全に覆われたアームは到達不能として拒否される。

## よく知られたアルゴリズム

以下の単独の例題は、現在の言語機能のみで書かれている。期待される出力は、対応する
`.out` ファイルにある。プレイグラウンドはリポジトリの 23 本すべてを含む。

| 例題 | 手法 | 既定の出力 |
|---|---|---|
| [Fibonacci](examples/fibonacci.ten) | 線形な累算器による再帰 | 最初の 12 個、`0` から `89` |
| [FizzBuzz](examples/fizzbuzz.ten) | 純粋な判定と順序付きの出力 | 1 から 30、Fizz/Buzz/FizzBuzz で置換 |
| [素数](examples/primes.ten) | 型付き述語と試し割り | 2 から 50 までの素数 |
| [最大公約数](examples/gcd.ten) | ユークリッドの互除法 | `21` と `6` |
| [コラッツ](examples/collatz.ten) | 偶奇による分岐と再帰的な列 | 7 から 1 までの列 |
| [九九](examples/times_table.ten) | 入れ子の再帰で各行を文字列として組み立てる | 9×9 の表 |
| [べき乗](examples/power.ten) | 指数の 1 ビットにつき 1 回の再帰（繰り返し二乗法） | `1024`・`243`・`1` |
| [二進表現](examples/binary.ten) | 商に対する再帰と桁の連結 | `0`・`5`・`10`・`255` の 2 進表記 |
| [回文数](examples/palindrome.ten) | 累算器による桁の反転 | 4 つの数とその反転 |
| [挿入ソート](examples/sort.ten) | ライブラリの一覧・畳み込み・切り捨て除算による比較 | `5 3 9 1 4` とその整列結果 |

入力の範囲は各ファイルの記述に従う。いずれも小さな教材プログラムであり、インタプリタ
の活性呼び出し 1024 の上限は変わらず適用される。各ファイル末尾の呼び出しは、手元でも
[ブラウザ・プレイグラウンド](https://c0ze.github.io/tenioha/#example=fibonacci)でも
変更できる。

ウェブサイトを手元でビルドして配信するには、`python scripts/serve_site.py` を実行し、
`http://127.0.0.1:8765` を開く。サイトのビルドは Python の標準ライブラリのみを使い、
ブラウザテストは Playwright を使う。設定と検査については
[PLAYGROUND.md](docs/PLAYGROUND.md) を参照。

## 先行事例と出典

Joomy Korkut による **[Kip](https://github.com/kip-dili/kip)** が直接の着想元である。
文法格と動詞の形が静的検査に関与するトルコ語の言語であり、実装は MIT ライセンスで
公開されている。調査用のローカル checkout は `../kip` にあり、参照した版は調査ノートに
記録してある。

**[なでしこ](https://nadesi.com/)** は、日本語の助詞による引数指定、語順の入れ替え、
敬語構文をすでに備えている。てにをははこれらを新規性として主張しない。てにをはが
置いている焦点は、厳密な助詞シグネチャ、通常の静的型、検査される効果からなる小さな
関数型の核である。

日本語には、Kip の格名を翻訳したものではなく、日本語自身の設計が必要である。

- `は` は主題を示すのであって、`が` を黙って代替してはならない。
- 助詞の役割は述語に依存する。`に`・`で`・`と` は普遍的な型の分類ではない。
- 語の境界を明示することで、形態素解析器への依存を避けられる。制限のない日本語文と
  自動的な活用は、より多くの機構を要する。
- 敬語は表層の機能としてはありうる。純粋性・効果・権限は、文体とは独立に明示的な
  意味論を持つべきである。

## 目的と限界

検証したいのは、日本語の引数役割が、型付き関数型プログラムを読みやすく、また教えやすく
するかどうかである。構文は実際の例と読者からの指摘に従って決めるべきものと考えている。
筆者は日本に住み、この言語を話す。

現在の実装に型推論はない。`の` による投射、`て` による連接、語の区切りのない自由な
日本語、活用エンジンのいずれも実装していない。同一シグネチャ内での `に` の重複は、
型による曖昧性解消を行わずに拒否する。評価器の活性呼び出しは 1024 で打ち切る。これは
コンパイラではなく参照インタプリタであり、研究上の新規性はここでは主張しない。それには
まだ行っていない文献調査を要する。

想定している応用の一つは、プログラミングゲーム
`~/projects/games/commit/commit+++` の高難度モードである。
